# ADR-002: административные операции не публикуются в MCP

## Context

MCP-сервер отдаёт ассистенту три инструмента: `resolve_project`, `next_id`, `list_identifiers`. REST
вдобавок заводит проекты и типы и включает типы в проектах. Права на это всё равно проверила бы
Policy, поэтому вопрос не в доступе, а в том, кто пополняет справочник.

## Decision

Справочник пополняет только человек через REST `/api/v1/admin/*`; в MCP инструментов для этого нет.

## Consequences

- Реестр закрыт затем, чтобы опечатка в origin или форк не заводили проект-призрак (принцип III
  конституции, FR-011). Инструмент `create_project` у ассистента под токеном администратора вернул
  бы ровно этот путь.
- Незарегистрированный проект — штатный ответ `resolve_project` (`registered: false`, `hint`), а не
  ошибка: ассистент передаёт человеку ключ и следующий шаг, решает администратор.
- FR-024 («MCP совпадает с REST») относится к трём общим операциям. Отсутствие остальных — граница
  поверхности, а не расхождение реализаций.
- Веб-экраны администратора справочник только показывают, поэтому единственный путь изменения —
  REST.
- Административный инструмент в MCP появляется только вместе с отменой этого ADR.
