# ADR-003: администратор снимает только последний номер пары

## Context

Тестовые и отменённые сразу после выдачи номера навсегда занимали нумерацию: реестр только
дописывался (принцип II). 2026-09-23 их пришлось удалять правкой production-базы. Разбор —
[specs/003-delete-last-identifier](../../specs/003-delete-last-identifier/research.md).

## Decision

Администратор в веб-консоли снимает последний номер пары «проект + тип», и `last_sequence`
откатывается до нового хвоста; номер из середины снять нельзя.

## Consequences

- Номер переиспользуется, но только с хвоста, поэтому пропусков в нумерации не бывает. Удалённый номер
  мог уже попасть в репозиторий потребителя — подтверждение предупреждает, решает администратор.
- `SequenceWithdrawer` берёт ту же блокировку строки `project_key_type`, что выдача (ADR-001), и
  больше ничего не блокирует: locking read хвоста ставил бы gap lock на соседнюю пару.
- `AppendOnlyQueryBuilder::withdraw()` — единственный открытый путь удаления через модель;
  `delete()`, `update()` и `upsert()` бросают, как раньше.
- Снятой темы в реестре нет, поэтому её повтор — первая выдача (`is_new: true`).
- В MCP и REST снятия нет (ADR-002).
- Отвергнуто:
  - удаление любого номера со сдвигом счётчика до максимума оставшихся — дыры, и номер из середины уже
    не вернуть;
  - удаление без отката счётчика — тестовые номера сжигают нумерацию;
  - мягкое снятие признаком — перечень не очищается.
