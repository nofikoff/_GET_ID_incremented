# ADR-001: выдачу номера сериализует блокировка строки-счётчика

## Context

Номер выдаётся без гонки и без пропусков (FR-001, FR-003). Исходное ТЗ предлагало
`SELECT MAX(sequence_number) ... FOR UPDATE` по `identifiers`, но первый номер новой пары «проект +
тип» запрашивается на пустом наборе строк, где такому запросу блокировать нечего. Разбор —
[research.md §R1](../../specs/001-incremental-id-registry/research.md).

## Decision

Счётчик `last_sequence` живёт в строке `project_key_type`: `SequenceIssuer` берёт её
`lockForUpdate()`, инкрементирует и вставляет запись реестра в одной транзакции.

## Consequences

- Строка появляется при включении типа в проекте, поэтому цель блокировки есть всегда, и выдачи
  одной пары встают в очередь. Разные пары друг друга не ждут.
- Строку связи нельзя удалять: вместе с ней уходит счётчик, и повторное включение выдало бы номер 1
  второй раз. Выключение типа — `is_enabled = false` (FR-016).
- Нарушение UNIQUE по `name_slug` — штатный повтор темы. Исключение обязано выйти из
  `DB::transaction()`: только тогда откат снимает инкремент, иначе проигравший гонку сжигает номер
  (FR-004a). Запись перечитывается снаружи, поэтому `SequenceIssuer` вызывается вне открытой
  транзакции — старый snapshot не увидел бы commit победителя.
- Нарушение UNIQUE по `sequence_number` — дефект сериализации: 500 и запись в лог, а не молчаливый
  повтор (FR-004b).
- Отвергнуто:
  - `SELECT MAX() FOR UPDATE` — на пустом наборе обе транзакции получают `NULL` и обе считают номер 1;
  - перепроверка темы внутри транзакции — consistent read в REPEATABLE READ не видит свежую запись
    конкурента, а locking read по отсутствующему ключу ставит gap lock и открывает deadlock между
    соседними парами;
  - уникальный индекс и retry без блокировки — число повторов растёт с нагрузкой, а их ошибки в логе
    неотличимы от дефекта;
  - `LOCK TABLES` и `GET_LOCK()` — блокируют шире нужного и привязывают домен к диалекту MySQL;
  - отдельная таблица-счётчик — дубль строки связи с тем же ключом.
- Решение доказывает только `tests/Concurrency/`: 50 процессов с общей меткой старта `--at`. Без
  метки холодный старт разводит процессы во времени, и тест зелёный на заведомо сломанной реализации.
