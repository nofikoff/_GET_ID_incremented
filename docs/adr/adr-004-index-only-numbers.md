# ADR-004: сервис выдаёт только номер

## Context

Тип ключа хранил шаблон (`ADR-{number:04d}`), и сервис вместе с номером возвращал собранное по нему
имя. Шаблон разошёлся с конвенцией репозиториев: сервис выдал `ADR-0003`, а документы именуются
`adr-003-<slug>.md` и `specs/003-<slug>/`. Разбор — [specs/004-index-only-numbers](../../specs/004-index-only-numbers/spec.md).

## Decision

get-id выдаёт только порядковый номер; имя документа собирает репозиторий-потребитель.

## Consequences

- `key_types.format_template` и `identifiers.formatted_id` удалены новой миграцией; выданные номера,
  темы, авторы и даты не тронуты. Имена, выданные до решения, не восстанавливаются — их собирают из номера.
- Правило «номер с ведущими нулями до трёх цифр» записано только в текстах для потребителя: справка
  (блок для `CLAUDE.md`), описание `next_id`, instructions MCP-сервера. Сервис его не применяет и не
  проверяет.
- Административный REST отвергает поле шаблона как неизвестное по общему правилу закрытого тела.
- Консоль называет номер «код типа + номер» («ADR 33») — в подтверждении и следе снятия, в отказе
  «не последний».
- Версия API не поднимается: клиенты — ассистенты, которые перечитывают описание инструмента в каждой
  сессии.
- Отвергнуто:
  - сменить шаблон ADR на трёхзначный и оставить отформатированное имя — сервис продолжает владеть
    чужой конвенцией, и расхождение вернётся со следующим репозиторием;
  - оставить колонки и перестать их читать — хранимые значения снова начнут читать.
