# Research: Веб-консоль администратора

## R1. Правила валидации — одно место для двух транспортов

**Decision**: наборы правил живут в `app/Http/Validation/*Rules` (статические методы по операции:
`ProjectRules::store()`, `::update()`, `KeyTypeRules::store()`, `::update()`,
`ProjectKeyTypeRules::set()`). API-запросы и веб-запросы возвращают их из своих `rules()`.

**Rationale**: API-запросы наследуют `ClosedBodyRequest` с `#[FailOnUnknownFields]` и JSON-ответом;
веб-запросу нужны служебные поля формы и штатный redirect back. Общими должны быть правила, а не
классы запросов. Тексты отказов тогда совпадают по построению (FR-018, SC-002).

**Alternatives considered**:
- Веб-запрос наследует API-запрос — `#[FailOnUnknownFields]` отвергает `_token` и `_method`, пришлось
  бы ломать закрытое тело исключениями.
- Веб-контроллер вызывает REST внутренним запросом — двойная аутентификация, JSON вместо ошибок формы.
- Правила в action — смешивает проверку формы ввода с операцией; FormRequest перестаёт быть
  точкой валидации, которой его делает фреймворк (принцип IV).

## R2. Проверка роли до поиска записи на веб-маршрутах

**Decision**: группа `/admin` в `routes/web.php` закрывается `EnsureAdministrator`, как REST, вместо
`can:administer`.

**Rationale**: `can:` — это `Authorize`, а штатный приоритет middleware ставит `SubstituteBindings`
раньше него. Сотрудник на `/admin/projects/999999` получил бы 404, на существующий id — 403, то есть
узнал бы, какие id существуют (FR-016, spec 001 FR-017). `EnsureAdministrator` уже поставлен перед
`SubstituteBindings` в `bootstrap/app.php`. Для списков разницы нет, но единая группа не оставляет
маршрута, где порядок забыт.

**Alternatives considered**: `can:` плюс `->withoutScopedBindings()` / ручной поиск в контроллере —
обход фреймворка ради того, что уже решено одной строкой приоритета.

## R3. Форма типов проекта и её приведение к набору

**Decision**: форма шлёт `types[<code>][enabled]` (checkbox) и `types[<code>][seed_sequence]`
(пустое = не менять). Веб-запрос приводит её к тому же `list<array{code, seed_sequence|null}>`, что
отдаёт `SetProjectKeyTypesRequest::types()`, и вызывает тот же `EnabledKeyTypes::replace()`. Отказы
`SeedBelowIssued` и `RetiredKeyType` веб-контроллер переводит в ошибку поля
`types.<code>.seed_sequence` / `types.<code>.enabled`. И ошибки валидации (индексные ключи
`types.<index>.*`), и доменные отказы (`position`) переводятся в ключи по коду через одну карту
`index → code` приведённого списка.

**Rationale**: форма перечисляет все активные типы, поэтому «набор целиком» совпадает с тем, что
видит администратор; неотмеченный тип выключается осознанно (FR-009). Позиционные ключи REST
(`types.0.code`) в форме неудобны — ошибка должна встать под строкой нужного типа.

## R4. Подтверждения без сборки фронтенда

**Decision**: `onsubmit="return confirm(...)"` на формах погашения; на форме типов — инлайн-скрипт
в partial, который перечисляет снимаемые включённые типы и спрашивает подтверждение, если их больше
нуля. Без JavaScript форма отправляется без подтверждения — сервер правила не ослабляет.

**Rationale**: FR-004, FR-009, FR-011 требуют подтверждения, а сборки фронтенда на хосте нет.
Подтверждение — UX-защита от случайного клика, не граница безопасности, поэтому сервер его не
проверяет.

**Alternatives considered**: промежуточная страница «вы уверены?» — второй запрос и второй шаблон ради
того же результата.

## R5. След изменений справочника (FR-019)

**Decision**: action после успешного изменения пишет `Log::info('registry change', [...])`:
`admin_id`, `admin_email`, `operation`, `entity`, `entity_id`, `changes` (изменённые поля «было →
стало», из `getChanges()` и `getOriginal()`). Канал — стандартный журнал приложения (`LOG_STACK=daily`
в production).

Запись обёрнута в `try/catch`: сбой канала логов пишется в `report()` и не откатывает изменение (FR-019).

**Rationale**: запись нужна для ответа «кто погасил проект», а не для отчётов; отдельная таблица
аудита — новая сущность, миграция и экран без запроса автора. Писать в action значит писать и для
REST-изменений — тот же вопрос «кто поменял» к ним относится так же.

**Alternatives considered**: `api_logs` — журнал REST и MCP, веб-формы в нём смешали бы поверхности;
пакет activity log — зависимость ради одной строки лога.

## R6. Выданные номера — пагинация по нескольким парам на одной странице

**Decision**: `IssuedIdentifiers::forPair(ProjectKeyType $pair, int $perPage = 50)` возвращает
`LengthAwarePaginator` с именем параметра страницы `page_<key_type_id>` (не код: PHP переписывает `.` и
пробел в именах GET-параметров в `_`, а код типа их допускает), от новых к старым по
`sequence_number`. Индекс — UNIQUE `(project_id, key_type_id, sequence_number)`, обратный проход
без filesort (spec 001 data-model.md §identifiers).

**Rationale**: у каждой пары свой листатель; общий `page` листал бы все блоки разом. Автор записи
подгружается `with('creator')`, чтобы страница делала постоянное число запросов.

## R7. Журнал — фильтры и поверхность

**Decision**: `ApiLogQuery` принимает `user_id`, `from`, `to` (даты, включительно, в таймзоне
приложения) и `surface` (`rest` | `mcp`). Поверхность определяется по `endpoint`: `/mcp` → MCP,
`/api/…` → REST — так `LogApiRequest` его и записывает. Сортировка по `created_at desc`, 50 на
страницу, `withQueryString()` сохраняет фильтр в ссылках пагинации. Фильтр валидируется веб-запросом
(`to` не раньше `from`).

**Rationale**: FR-015 требует фильтр в адресе страницы — GET-форма это даёт без состояния.
Отдельной колонки поверхности в `api_logs` нет и не нужно: префикс пути однозначен.

**Alternatives considered**: колонка `surface` — миграция журнала ради признака, выводимого из
уже хранимого пути.

## R8. Одновременное заведение в вебе

**Decision**: `CreateProject` и `CreateKeyType` ловят `UniqueConstraintViolationException` так же,
как API-контроллеры сейчас (`RethrowsUniqueConflictAsValidation`); `ValidationException` в вебе
штатно превращается в redirect back с ошибкой под полем.

**Rationale**: механизм уже есть и одинаков для обоих транспортов, если перенести вызов в action
вместе с правилами (R1).
