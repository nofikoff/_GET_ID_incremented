# Access & Parity Checklist: Веб-консоль администратора

**Purpose**: Проверить качество требований к доступу, защите форм, подтверждениям, единому источнику правил,
неизменности REST и MCP, следу изменений и фильтрам журнала — до реализации.
**Created**: 2026-09-23
**Feature**: [spec.md](../spec.md) · [plan.md](../plan.md) · [contracts/web-console.md](../contracts/web-console.md)

`[x]` означает, что reviewer признал требование написанным достаточно полно и однозначно, а не что
реализация готова.

## Доступ

- [x] CHK001 - Требование «только администратор» распространено на каждую страницу и каждую форму, включая просмотр номеров и журнала, а не только на изменения? [Coverage, Spec §FR-016]
- [x] CHK002 - Определено, что отказ сотруднику без роли одинаков для существующего и несуществующего идентификатора на всех маршрутах с идентификатором? [Clarity, Spec §FR-016, Contract]
- [x] CHK003 - Определено поведение для гостя (не вошедшего) отдельно от сотрудника без роли? [Gap]
- [x] CHK004 - Определено, что происходит с открытой сессией администратора, у которого роль сняли консольной командой? [Edge Case, Gap]
- [x] CHK005 - Указано, раскрывает ли журнал параметры запросов (в том числе формулировки тем) только администратору и нет ли в них секретов? [Completeness, Spec §FR-014]

## Защита форм и подтверждения

- [x] CHK006 - Требование защиты от подделки запроса покрывает все изменяющие маршруты, а поведение при недействительной защите описано? [Coverage, Spec §FR-017, Edge Cases]
- [x] CHK007 - Перечислены все действия, требующие подтверждения, и условие, при котором оно спрашивается? [Completeness, Spec §FR-004, §FR-009, §FR-011]
- [x] CHK008 - Явно сказано, что подтверждение — защита от случайного действия, а не граница безопасности, и сервер его не проверяет? [Clarity, Plan research R4]
- [x] CHK009 - Определено, требует ли подтверждения возврат проекта или типа в обращение? [Gap]

## Единый источник правил и совместимость

- [x] CHK010 - Требование «те же правила и те же формулировки отказов» сопоставлено с каждой операцией административного REST без пропусков? [Completeness, Spec §FR-018, §SC-002]
- [x] CHK011 - Определены отказы, которые есть только в консоли (позиция ошибки под строкой типа, фильтр журнала), и их тексты? [Gap, Contract]
- [x] CHK012 - Измеримо ли «поведение REST и MCP не меняется» — через неизменность ожиданий существующих тестов? [Measurability, Spec §SC-003]
- [x] CHK013 - Согласованы правила о начальном значении в консоли (пустое поле = не менять) и в REST (отсутствие поля = не менять)? [Consistency, Spec §FR-007]
- [x] CHK014 - Согласовано требование «адрес и ключ проекта не меняются» между консолью и REST, где `repo_url` в PATCH отвергается? [Consistency, Spec §FR-004]
- [x] CHK015 - Определено поведение формы типов проекта для типов, выведенных из обращения, но включённых в проекте ранее? [Edge Case, Spec §FR-006, §FR-010]

## След изменений

- [x] CHK016 - Определён состав записи следа: кто, операция, сущность, изменённые поля «было → стало»? [Completeness, Spec §FR-019]
- [x] CHK017 - Указано, распространяется ли след на изменения через REST, а не только через консоль? [Ambiguity, Spec §FR-019]
- [x] CHK018 - Определено, что происходит, если запись следа не удалась: откатывается ли изменение справочника? [Exception Flow, Gap]

## Журнал обращений

- [x] CHK019 - Однозначно определены границы диапазона дат (включительно ли «по», в какой таймзоне)? [Clarity, Spec §FR-015]
- [x] CHK020 - Однозначно определено, как запись относится к поверхности REST или MCP? [Clarity, Spec §FR-015]
- [x] CHK021 - Описаны пустой результат и некорректный фильтр (дата «с» позже «по», несуществующий сотрудник)? [Coverage, Spec Edge Cases]
- [x] CHK022 - Указано, доступны ли в фильтре деактивированные сотрудники, чьи записи ещё в журнале? [Gap]
