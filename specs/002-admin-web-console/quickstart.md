# Quickstart: проверка веб-консоли

Окружение — как в [quickstart 001](../001-incremental-id-registry/quickstart.md) §1–2: стек поднят,
вход через Google, адрес из `ADMIN_EMAILS` — администратор.

## 1. Проект без терминала (SC-001)

1. `/admin/projects` → «Новый проект»: адрес `git@gitlab.cas.ai:team/backend.git`, имя `Backend`.
   Ожидаемо: карточка проекта, ключ `gitlab.cas.ai/team/backend`.
2. Ещё раз тот же репозиторий в форме `https://gitlab.cas.ai/team/backend`. Ожидаемо: форма с ошибкой
   под адресом, введённые значения на месте.
3. На карточке отметить `ADR` с seed `12` и `spec` без seed, сохранить. Ожидаемо: следующий номер
   `ADR` — 13, `spec` — 1.
4. Проверка через выдачу (ассистентом по MCP или REST, quickstart 001 §4): первая выдача `ADR` — `ADR-0013`.

## 2. Отказы

- seed `5` для `ADR` после выдачи 13 → ошибка под полем seed `ADR`, набор прежний.
- Снять `ADR` → браузер спрашивает подтверждение с названием `ADR`; после подтверждения выдача по
  `ADR` отвергается `type_not_enabled`, следующий номер на карточке прежний.
- Тип с шаблоном `RFC-{name}` → ошибка под шаблоном «нет номера».

## 3. Просмотр

- Карточка проекта: выданные номера `ADR` от новых к старым с автором и датой.
- `/admin/logs?user_id=<id>&from=<сегодня>&to=<сегодня>&surface=mcp`: только MCP-обращения этого
  сотрудника за сегодня; та же ссылка в новой вкладке — тот же результат.

## 4. Доступ

Под сотрудником без роли: `/admin/projects`, `/admin/projects/999999`, отправка любой формы — 403,
ответ для несуществующего id не отличается.

## 5. Регрессия

`make test` — зелёный, тесты REST и MCP без правки ожиданий (SC-003).
